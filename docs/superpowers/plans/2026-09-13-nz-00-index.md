# Net-Zero Scenario Tool (Part 2) — Implementation Plan Index

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the Part 2 net-zero scenario engine, its data pipeline, the ticker risk panel and the `/portfolio` page, exactly as specified by `Final_Part_2.pdf` and the approved design spec.

**Architecture:** A `uv`-managed Python pipeline in `data/pipeline/nz/` builds company inputs (source-split emissions, TTM financials, DE/BEN, float caps) into Supabase `nz_*` tables. A pure TypeScript engine in `lib/netzero/` (TBR → TOPSIS/entropy per sector → dispersion → books → sensitivity) runs in the browser. Server components load the tables once; client components run the engine live.

**Tech Stack:** Next.js 16.3 (App Router, `cacheComponents: true`), React 19.3, TypeScript 5, Tailwind 3 + shadcn/ui (new-york), Supabase (`@supabase/ssr`), vitest 5, Python 3.14 via `uv`, pandas, openpyxl, pyxlsb, yfinance, requests, psycopg2-binary, google-genai, pytest.

**Spec:** `docs/superpowers/specs/2026-09-13-net-zero-scenario-design.md` (read it before any task; the PDF `Final_Part_2.pdf` is the reference behind it).

## Global Constraints

- The PDF is the single source of truth. Any rule not in the PDF is a **[gap]** or **[decision]** and gets an entry in `docs/decisions-log.md` in the same commit that implements it.
- Normalisation is min-max **within GICS sector** (spec D1). Part 1 content is used only where the Part 2 PDF cites it.
- `docs/superpowers/` exists only on `part-2` and must never reach `main`.
- Every phase runs on its own branch `nz/pN-<name>` cut from `part-2`, merged back into `part-2` with `git merge --no-ff`. Never merge to `main`. Ask the user before any `git push`.
- Commits: Conventional Commits, author `Rajitpal Singh <singh.rajitpal@gmail.com>` (already the repo's git config), **no AI co-author trailer**.
- Secrets (`GEMINI_API_KEY`, `SEC_USER_AGENT`, `PGHOST`, `PGPORT`, `PGUSER`, `PGPASSWORD`, `PGDATABASE`) live only in `.env.local` or the shell; never in code or git.
- Any write to the shared Supabase project (DDL or loads) needs the user's explicit OK first.
- Gemini: model `gemini-2.5-flash`, free tier, temperature 0, JSON schema output, `thinking_budget=0`, responses cached in `data/raw/nz/gemini_cache/`.
- Engine defaults: MAC mid-points 30 / 120 / 200 / 150 / 15 USD/t (scope2, combustion, fleet, process, fugitive) until `mac_costs.csv` is confirmed; TBR IQR threshold 0.25 years; score IQR threshold 25; capital USD 1,000,000,000; mandate long-only; weight cap 0.40.
- Book limits: long/short name ≤ 3% of gross, sector ≤ 20% of gross, gross 200% of capital, net 0; long-only active ±2pp, name ≤ 5%, sector weight = benchmark.
- Next.js 16: pages that read cookies, Supabase or `searchParams` must do so inside `<Suspense>` (see `app/protected/page.tsx`); `searchParams` is a `Promise`. Read `node_modules/next/dist/docs/` before writing Next code.
- Done for a phase = tests + `npm run lint` + `npm run build` pass in-session with output shown, the phase's result is visible on a page (once data is loaded), decisions-log entries written, `/code-review` run on the branch, then merged into `part-2`.
